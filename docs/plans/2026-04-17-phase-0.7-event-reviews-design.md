**Audience:** same invite list, selectively expanded (~80–120 users).
**Risk killed:** event-level reviews are signal, not noise; brigading doesn't damage organizer relationships.

## Scope

**In:**
- Unhide event-level reviews on `/events/<slug>` once per-event attendance density crosses threshold (default ≥3 `Review` rows on that event).
- Gate review authorship: only users with `Attendance.status='went'` on that specific event can submit a review. Form rejects others with "You can review this event after attending."
- Event-level signal aggregates in `/events` list: small star-rating chip on event cards where applicable.
- Optional "most-reviewed" sort on `/events`.
- `FeatureFlag.key="event_reviews_displayed"` controls surface.

**Out:**
- Any change to organizer reviews (already live from 0.5/0.6).
- Reviewing events you didn't attend — banned by construction.
- Aggregate scores across multiple events ("this organizer's average event rating") — compute maybe, display is a judgment call defer to phase start.

## Data model deltas

None. `Review` model already has `event` FK from 0.1 (F2 foresight). `Attendance` model has `status='went'` from 0.4.

Possibly add a nightly task that auto-sets `Attendance.status` from `'going'` to `'went'` 24h after `Event.end`, so users don't have to manually mark attendance — makes review gating actually work at scale.

```python
# django-q2 nightly task
def finalize_attendance():
    past_events = Event.objects.filter(end__lt=now() - timedelta(hours=24))
    Attendance.objects.filter(
        event__in=past_events,
        status="going",
    ).update(status="went")
```

## UI deltas

- `/events/<slug>`: reviews section appears below description when `rating_count >= 3`. Sortable by recent / highest / lowest. Display reviewer's display name + date attended.
- Review form on `/events/<slug>`: only renders if `request.user.attendances.filter(event=event, status='went').exists()`.
- Event card on `/events`: add small star chip `★ 4.2` when `rating_count >= 3`.

## Test plan

- Review-gate enforcement: user without `'went'` attendance → form 403; attempting direct POST → 403.
- Threshold hiding: event with 2 reviews → no rating displayed on card or detail; third review crosses threshold → appears.
- Auto-finalize attendance: task moves `'going'` → `'went'` for events ended >24h ago; events with `end=None` are skipped.
- Flag on event review: creates `Flag` with `review_fk` set; auto-hide rule from 0.5 applies.

## Go/no-go to 1.0

- At least 10 events have ≥3 event-reviews each — real density.
- Review-gate (attended-only) rejects >0 attempted unauthorized submissions without breaking legitimate ones.
- No brigading incident on an event review within 4 weeks of surfacing.
- Maintainer workload unchanged or reduced vs. 0.6.

## Rollback

- Flip `event_reviews_displayed=False` → reviews collected silently, display hidden. Data safe.
- If review-gate finalize-attendance task misfires (e.g., events with null end dates flip incorrectly), run a backfill to restore.
