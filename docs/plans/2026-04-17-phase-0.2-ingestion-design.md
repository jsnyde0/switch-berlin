## Scope

**In:**
- Telegram bot (python-telegram-bot) accepting forwards from allowlisted sender IDs. Runs as a separate Docker service using long-polling (`Application.run_polling()`).
- URL enrichment pipeline: httpx fetch + markdownify on any URLs found in the forwarded message. Best-effort per URL — partial enrichment proceeds to extraction.
- pydantic-ai extraction: `RawMessage` (text + enriched content) → `EventDraft` schema → `Event(status='draft')`.
- Admin review UX upgrades: side-by-side diff (raw vs parsed) via custom `change_form.html` template, bulk approve, "approve + publish" one-click.
- Organizer allowlist enforcement: bot rejects forwards from unknown senders with a polite reply; admin sees rejected attempts in a log.
- GDPR consent capture (F5) happens *here* — on first organizer approval in admin, consent fields populate.
- django-q2 scheduled task: nightly `archive_past_events` + `soft_purge_rawmessages_older_than_90d`.

**Out:**
- Public templates / any anonymous-reachable URL — phase 0.3.
- Auth beyond `is_staff` for maintainer access to admin — phase 0.3+.
- Event/organizer feeds to any UI — phase 0.3.

## Data model deltas

Additions to 0.1 schema:

### Migration: add `needs_review` to `RawMessage.extraction_status`

The existing `RawMessage.extraction_status` choices (`pending`, `extracted`, `failed`, `skipped`) need a new value: `needs_review` — used for low-confidence extractions (<0.4) that skip draft creation and await manual triage.

### `ingestion.ExtractionAttempt`
```python
class ExtractionAttempt(models.Model):
    raw_message = FK(RawMessage, on_delete=CASCADE, related_name="attempts")
    event = FK(Event, null=True, blank=True, on_delete=SET_NULL, related_name="extraction_attempts")
    attempted_at = DateTimeField(auto_now_add=True)
    model_name = CharField(max_length=100)  # e.g., "claude-opus-4-7"
    prompt_version = CharField(max_length=50)  # monotonic: "v1", "v2", etc.
    raw_response = JSONField()
    extracted_draft = JSONField(default=dict, blank=True)  # serialized EventDraft
    confidence_score = FloatField(null=True, blank=True)
    success = BooleanField(default=False)
    error = TextField(blank=True)
```

The `event` FK provides explicit provenance: which attempt produced which draft Event. When a RawMessage has multiple attempts (retries with different prompts), the linked Event makes the successful attempt unambiguous.

### `ingestion.ApprovedSender`
```python
class ApprovedSender(models.Model):
    telegram_user_id = CharField(max_length=100, unique=True)  # canonical: str(int), no prefix
    telegram_handle = CharField(max_length=100, blank=True)
    organizer = FK(Organizer, null=True, blank=True, on_delete=SET_NULL)
    approved_at = DateTimeField(auto_now_add=True)
    notes = TextField(blank=True)
```

Telegram user IDs are stored as the string representation of the integer (e.g., `"123456789"`). Both `ApprovedSender.telegram_user_id` and `RawMessage.sender_id` use this canonical format to ensure allowlist lookups match.

### Deduplication constraint on `RawMessage`

Add a unique constraint on `(source_type, channel_id, message_id)` for Telegram forwards where `message_id` is available. This prevents duplicate `RawMessage` rows (and wasted LLM calls) when the same message is forwarded multiple times. For messages without `message_id`, fall back to a content hash of `text` stored in a new `content_hash` field (nullable, indexed).

Consent fields on `Organizer` already exist from 0.1 (F5). This phase is when they get populated.

## Ingestion pipeline

```
┌────────────────┐
│ Telegram bot   │ ← forward from allowlisted sender
│ (polling svc)  │
└────────┬───────┘
         │ sync_to_async ORM calls
         ▼
┌────────────────────┐
│ RawMessage created │
│ extraction=pending │
│ (dedup check first)│
└────────┬───────────┘
         ▼ (django-q2 async_task enqueued)
┌────────────────────┐
│ URL enrichment     │
│ (httpx + markdown) │
│ best-effort/URL    │
└────────┬───────────┘
         ▼
┌────────────────────────┐
│ pydantic-ai extraction │
│ → EventDraft schema    │
└────────┬───────────────┘
         ▼
┌─────────────────────────────────┐
│ Post-extraction matching:       │
│ organizer, venue, tags          │
└────────┬────────────────────────┘
         ▼

│ Event(status='draft')  │
│ ExtractionAttempt saved│

┌────────────────────────┐
│ Admin review           │

│ reject → rejected      │
└────────────────────────┘
```

## Bot deployment model

The Telegram bot runs as a **third Docker service** (`bot`) alongside `app` and `qcluster`, using `Application.run_polling()`. This avoids needing a public webhook URL (which would intersect with ADR-002 D2's closed-beta posture).

The bot is **not a public-facing product surface** under ADR-002 D2: it performs no public function — non-allowlisted users receive only a rejection message and no product data is exposed. The bot username is shared privately with approved organizers only.

### Async/sync boundary

python-telegram-bot v21+ runs its own asyncio event loop. All Django ORM operations inside bot handlers use `sync_to_async` (Django 5+/6 standard). Task enqueuing uses `sync_to_async(async_task)()` from django-q2.

## `EventDraft` schema (pydantic-ai output)

```python
class EventDraft(pydantic.BaseModel):
    title: str
    description: str | None = None
    organizer_name: str  # matched post-extraction; see "Entity matching" section
    venue_name: str | None = None  # matched post-extraction; see "Entity matching"
    start: datetime
    end: datetime | None = None
    price_min_cents: int | None = None
    price_max_cents: int | None = None
    is_free: bool = False
    external_url: str | None = None
    tags: list[str] = []  # matched post-extraction; see "Entity matching"
    confidence: float  # self-reported 0-1
```

Extraction prompt pinned via `prompt_version` (monotonic: `"v1"`, `"v2"`, etc.). Prompt templates live as constants in the extraction task module (e.g., `ingestion/tasks.py`). Low-confidence drafts (<0.4) skip the draft creation step and stay at `RawMessage.extraction_status='needs_review'` for manual triage.

## Entity matching (post-extraction)

After pydantic-ai produces an `EventDraft`, three fields need mapping to Django model instances:

### Organizer matching
1. Case-insensitive exact match on `Organizer.name`.
2. If no exact match, try `trigram_similar` (pg_trgm) with threshold 0.6.
3. If still no match or ambiguous (multiple candidates above threshold): set `Event.organizer = NULL`, store `organizer_name` in `ExtractionAttempt.extracted_draft` for admin resolution.
4. The LLM prompt includes the list of known `Organizer.name` values to bias toward existing names.

### Venue matching
1. Case-insensitive exact match on `Venue.name`.
2. No fuzzy fallback — venue names vary too much (abbreviations, German/English). Unmatched venues set `Event.venue = NULL` and store `venue_name` in the draft JSON for admin to resolve.
3. The LLM prompt includes the list of known `Venue.name` values.

### Tag matching
1. Case-insensitive exact match on `Tag.slug`.
2. Matched tags are set as the M2M relation on the Event.
3. Unmatched tag strings are stored in `Event.suggested_tags` (new `JSONField(default=list, blank=True)`) for admin review.
4. The LLM prompt includes the list of existing `Tag.slug` values so it prefers known tags.

## Admin review UX

- Event change form: custom `change_form.html` template override — left column shows `RawMessage.text` + `enriched_payload` pretty-printed; right column shows editable `Event` fields. "Apply draft" button (vanilla JS, ~50-100 lines) reads `ExtractionAttempt.extracted_draft` from a JSON script block and populates form inputs. Budget: 1-2 days for the custom template + JS.
- List filter by `status` defaults to `draft`.
- Bulk action "Approve + publish" on selected drafts.
- Quick keyboard shortcuts (vanilla JS): `A` approve, `R` reject, `J/K` next/prev.

## URL enrichment

- Extract URLs via regex from `RawMessage.text`.
- For each URL, `httpx.get(timeout=10)` with a real User-Agent.
- Convert HTML → markdown via `markdownify`.
- Store concatenated markdown in `RawMessage.enriched_payload['url_content']`.
- Cap total enriched size at 20KB; truncate with a marker.
- **Best-effort per URL**: if one URL fails, enrichment continues with the remaining URLs. Only log the failure — never block extraction due to enrichment failure. The LLM works with whatever context is available; admin can always review raw text.
- **SSRF protection**: before fetching, the URL's hostname is resolved and the resulting IP is checked against private/reserved ranges (RFC 1918, loopback, link-local). Requests to internal addresses are rejected and logged. This is implemented in `enrichment.py`.

## Telegram bot

- python-telegram-bot async handler, deployed as a dedicated Docker service using `run_polling()`.
- On first interaction: send consent text (German + English) — this is the legal basis trail even though no public surface exists yet.
- Non-allowlisted sender: "This bot only accepts forwards from approved organizers. To request access, DM @jsnyde0."
- Allowlisted sender: acknowledge with "Received. Will appear in the next review batch."
- Non-text messages (images, stickers, voice): reject with "Only text messages and text forwards are supported." Create a `RawMessage` with `extraction_status='skipped'` and a note for audit purposes.
- Rate limit: 100 messages/hour/sender; tracked in-memory (acceptable for single-worker deployment — resets on restart, which is fine since the limit is a safety valve, not a billing control).
- All ORM operations use `sync_to_async`; task enqueuing via `sync_to_async(async_task)()`.

## Scheduled tasks

### `archive_past_events`
Nightly. Archives events where `end < now - 24h` (or `start < now - 24h` when `end` is NULL). Only `published` events are archived — `draft` events are left as-is for admin to handle (archiving an unreviewed draft silently would hide work).

### `soft_purge_rawmessages_older_than_90d`
Nightly. **Soft purge**: nullifies `RawMessage.text` and `RawMessage.raw_payload` for rows older than 90 days, but preserves the `RawMessage` row itself and all linked `ExtractionAttempt` rows. This maintains the provenance chain (`Event → RawMessage → ExtractionAttempt`) and the audit trail of which model/prompt produced each extraction, while clearing PII-bearing raw content. The `enriched_payload` is also nullified (may contain PII from fetched URLs).

## Logging

Structured logging via Logfire at each pipeline stage:

- **Bot**: message received (sender_id, message_id, is_allowlisted)
- **URL enrichment**: per-URL (URL, status_code, content_length_bytes, duration_ms)
- **LLM extraction**: model_name, prompt_version, token_usage, latency_ms, confidence_score
- **Draft creation**: event_id, organizer_matched (bool), venue_matched (bool), unmatched_tags count
- **Extraction skip**: reason (low_confidence, non_text, duplicate)
- **Admin action**: event_id, action (approve/reject/edit), time_spent_seconds (if feasible)

## Feature flags (ADR-003 F9)

Bot enable/disable is controlled via a Django setting (`BOT_ENABLED` env var), using ADR-003 F9's explicitly permitted "or a settings entry" option. The flag is checked at the bot message handler level. When disabled, the bot responds to all messages with "Bot is temporarily offline."

This is compliant with ADR-003 F9. A DB-backed flag (flippable in the admin "feature switches" view without a redeploy) is deferred to a future bead once there is operational pressure for runtime toggling.

## Test plan

- Fixture-based extraction tests: 10 real Telegram forwards (anonymized) → assert extracted `EventDraft` matches golden output within tolerance.
- Integration test: bot receives forward → RawMessage created → task enqueued → draft Event created → admin approves → Event.status='published'.
- Confidence threshold test: mocked <0.4 confidence does NOT create an Event; RawMessage stays at `extraction_status='needs_review'`.
- URL enrichment test: mock httpx, assert markdown lands in `enriched_payload`.
- Partial enrichment test: 3 URLs, one times out → enrichment proceeds with 2, extraction still runs.
- Failure path test: all URLs fail → extraction still runs with raw text only.
- Deduplication test: same message forwarded twice → only one RawMessage created, second forward returns "already received" to sender.
- Non-text message test: image/sticker forward → RawMessage with `extraction_status='skipped'`, bot replies with "only text supported."
- Scheduled task test: `archive_past_events` archives published events where `end < now - 24h`; leaves drafts untouched; falls back to `start` when `end` is NULL.
- Soft purge test: `soft_purge_rawmessages_older_than_90d` nullifies text/payload but preserves RawMessage row and ExtractionAttempt rows.
- Entity matching tests: organizer exact match, organizer fuzzy match, organizer no-match → NULL; venue exact match, venue no-match → NULL; tag match, tag no-match → suggested_tags.

## Go/no-go to 0.3

Over 2 consecutive weeks of real Telegram forwards from 3+ allowlisted senders:
- ≥70% of drafts approvable with ≤1 field edit.
- Median admin review time ≤20 seconds per event.
- Total daily admin ≤15 minutes at 10–20 events/day (ADR-001 D3 budget).
- Zero extraction failures silently lost (every failure visible as a `SourceFailure`).

## Rollback

- Disable bot via `BOT_ENABLED=False` Django setting (per ADR-003 F9).
- `RawMessage` and `Event(status='draft')` rows persist; no data loss.
- Re-run extraction later with a new prompt version if the first attempt was bad.
