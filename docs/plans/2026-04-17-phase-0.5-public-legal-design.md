## Legal gate (ships as one sprint before 0.5 public opening)

**This is the compliance sprint. Agent-reviewed, not lawyer-reviewed (per ADR-002 D2 — accepted risk).** Checklist:

### JuSchG — age gate
- `AgeGateMiddleware`: first request without `age_gate=ok` cookie → 303 redirect to `/age-check` interstitial.
- Middleware ordering: `AgeGateMiddleware` runs AFTER `LoginWallMiddleware`. When `PUBLIC_READ_ENABLED=False` (rollback), the age gate bypasses itself — restoring pure 0.4 posture.
- Interstitial page: "You must be 18+ to enter. [Yes, I am 18+] [Leave]." The "Leave" button redirects to `google.de`.
- Cookie: session-only or 365-day persistent at user's choice. The 365-day option is classified as "strictly necessary" under TTDSG §25(2) — an age-verification cookie for a legally-required gate is exempt from consent requirements. No cookie banner needed.
- Applies to every route except `/impressum`, `/privacy`, `/terms`, `/healthz`, `/age-check`, `/robots.txt`.
- Crawler bypass: the age gate only applies to responses with `text/html` content type; bot user agents (Googlebot, etc.) are exempt so SEO indexing is not blocked.
- German + English copy. German phrasing is a deliverable reviewed in the legal-review finalization step (JuSchG-appropriate wording carries legal nuance). Interstitial must be keyboard-navigable and screen-reader accessible (WCAG AA).

### DSA — takedown + contact
- `/impressum` page with responsible party details (maintainer name + address).
- `/takedown` endpoint: form (event URL, reason, reporter email, optional identity verification). Rate-limited: 5 submissions per IP per hour (django-ratelimit).
- Takedown submissions are saved to the `Flag` model (with `reporter=null` for anonymous) AND trigger an email notification asynchronously via django-q2. The Flag row is the source of truth; email is notification only.
- Email relay: submissions land in a filtered Gmail label (no ticketing system per ADR-002). Email send failures are logged to a `core.EmailFailure` record visible in admin, so DSA compliance does not depend on email reliability.
- Published SLA: "We aim to review takedown requests within 72 hours."
- Trusted Flagger handling: placeholder endpoint; no registered flaggers yet.
- Anonymous takedown-form flags (`reporter=null`) do NOT count toward the auto-hide threshold — only flags from authenticated users count, preventing trivial content denial-of-service.

### GDPR — consent + opt-out
- `Organizer.consent_*` fields populated since 0.2 (F5). This is when they become legally load-bearing.
- `/organizer-opt-out` endpoint: form where an organizer can request removal. Identity verification via `ingestion.ApprovedSender.telegram_user_id` match (bot-verified, not spoofable). Fallback: manual processing through the takedown inbox if the organizer cannot verify via Telegram.
- Data-retention policy: `RawMessage` purged after 90 days (django-q2 nightly task from 0.2 continues).
- `/privacy` page explains: what data we collect (events, organizer info, user account, attendance), lawful basis per category, retention, rights.
- Cookie policy: no cookie consent banner needed. The only persistent cookie is the age-gate cookie, which is "strictly necessary" under TTDSG §25(2). All other cookies are session-only. No tracking cookies are used (MapLibre + OSM tiles, no Google Maps per ADR-002 D4).

### Legal pages

- `/privacy` (data handling)

- All linked from every page footer. Note: the current footer (`cotton/footer.html`) contains placeholder content ("About us", "Contact", "Jobs", "Press kit") — this is a full rewrite, not an append. Remove non-applicable placeholders and replace with legal-page links.

### Telegram bot

### Hardening (pre-public)
- Switch drawer endpoint from PK-based (`/events/<int:event_id>/drawer/`) to slug-based (`/events/<org_slug>/<event_slug>/drawer/`). Also update `attend` endpoint similarly. Full scope of the slug migration:
  - **Backend:** New URL patterns using `<slug:org_slug>/<slug:event_slug>` for drawer and attend views. Old PK-based URLs removed.
  - **GeoJSON payload:** Remove `event_id` (integer PK) from marker features in `events/views.py`. Use `org_slug` + `event_slug` (already present) for all URL construction.
  - **map.js:** Refactor drawer URL construction from `/events/<event_id>/drawer/` to `/events/<org_slug>/<event_slug>/drawer/`. Update Alpine store's `selectEvent()` to use a composite key (`org_slug/event_slug`) instead of integer PK. Update `events:selection-changed` filter expression in the map layer paint property to use a string-matchable property.
  - **Tests:** Update integration tests that assert on `event_id` in GeoJSON responses.
- Remove `X-Robots-Tag: noindex, nofollow, noarchive` header from public routes. Currently hardcoded on every response in `LoginWallMiddleware` — must be conditional: set the header only when `PUBLIC_READ_ENABLED=False` (rollback) or on authenticated-only routes.
- `robots.txt` served by a Django view (not static template) that checks `PUBLIC_READ_ENABLED`: returns `Allow: /` when True, `Disallow: /` when False.
- OG meta tags on event detail and organizer profile pages, wrapped in a template conditional on `PUBLIC_READ_ENABLED` — suppressed during rollback to avoid share-links pointing at a login wall.

## Scope (post-gate)

**In:**
- Login-wall middleware restructured with **two-tier prefix design**:
  - `ALWAYS_PUBLIC_PREFIXES`: routes reachable regardless of `PUBLIC_READ_ENABLED` — `/accounts/`, `/healthz`, `/robots.txt`, `/impressum`, `/privacy`, `/terms`, `/takedown`, `/age-check`.
  - `PUBLIC_READ_PREFIXES`: routes reachable only when `PUBLIC_READ_ENABLED=True` — `/events`, `/o/`, `/`.
  - Middleware logic: if path in `ALWAYS_PUBLIC_PREFIXES` → pass; elif `PUBLIC_READ_ENABLED` and path in `PUBLIC_READ_PREFIXES` → pass; else → enforce auth. This makes rollback correct by construction.
- Signup still invite-only (InviteCode model + NoSignupAdapter shipped in 0.4); all writes (attend, follow, future review/flag) still require approved account.
- `robots.txt` opens up (allow crawling of public routes) — served dynamically, see Hardening. OG tags on event + organizer pages (per ADR-002 D4 "trap feature" — OG tags are fine NOW that we're post-gate), conditional on `PUBLIC_READ_ENABLED`.
- Organizer ratings DISPLAYED when `rating_count >= MIN_RATINGS_FOR_DISPLAY` (initial value: 3, per ADR-003 F2): on `/o/<slug>`, show average + count.
- Event ratings COLLECTED (form works, row saved) but NOT DISPLAYED (per ADR-003 F2 — wait for 0.7 when per-event N supports threshold).
- Flag / report endpoint: flag button on every event + organizer page (authenticated users only). Flags land in `Flag` model. Per-user rate limit: 10 flags per day. Triage via daily email digest (django-q2 scheduled task that queries unresolved flags and sends a summary). No in-app triage UI (F9).
- Auto-hide rule: `AUTO_HIDE_FLAG_THRESHOLD` (initial value: 3) authenticated-user flags on a single target → hide from public (admin still sees). Pulled forward from 0.6 roadmap — flags without auto-hide create an unbounded manual-triage obligation.
- All public-facing querysets use custom manager methods (`Event.objects.visible()`, `Organizer.objects.visible()`) that filter `hidden=False`. Entry points: `event_list`, `event_detail`, `event_drawer`, `organizer_profile` (both upcoming and past events querysets), and any future public views.
- Kill-switches (F9): All feature flags consolidated into the `core.FeatureFlag` DB table. Existing env-var flags (`LOGIN_WALL_ENABLED`, `MAP_ENABLED`, `INVITES_ENABLED`) are migrated into the DB via a data migration; the `settings.py` env-var definitions and the context processor are updated to read from `FeatureFlag` via a cached `get_flag(key, default)` helper. One read path, one toggle mechanism.
- Nightly `django-q2` task: recompute `Organizer.follower_count`, `Event.attendance_count`, `Organizer.avg_rating` (F8). These denormalized fields are new in 0.5.

**Out:**
- Open (non-invite) signup — phase 1.0 (admin-reviewed form).
- Event reviews displayed — phase 0.7.
- Organizer self-service edits — phase 1.0.
- In-app moderation console — ADR-002 D4 cut; email digest only.

## Data model deltas

**Carry-overs from 0.4 (already in DB — no migration needed):**
- `accounts.InviteCode` — invite code model + allauth adapter
- `events.Attendance` — user × event attendance status
- `organizers.OrganizerFollow` — user × organizer follow
- `reviews.Review` — rating + body for organizer or event (XOR FK). **New constraint in 0.5:** add `UniqueConstraint(fields=["author", "organizer"], condition=Q(organizer__isnull=False), name="one_review_per_author_per_organizer")` and equivalent for events. Prevents a single user from submitting multiple reviews and crossing the display threshold alone. Review form uses `update_or_create`.

**New in 0.5:**

### `reviews.Flag`
```python
class Flag(models.Model):
    reporter = FK(User, null=True, blank=True, on_delete=SET_NULL)  # null = anonymous takedown form
    organizer = FK(Organizer, null=True, blank=True, on_delete=CASCADE, related_name="flags")
    event = FK(Event, null=True, blank=True, on_delete=CASCADE, related_name="flags")
    review = FK("reviews.Review", null=True, blank=True, on_delete=CASCADE, related_name="flags")
    reason = CharField(choices=[("spam","Spam"),("inaccurate","Inaccurate"),("harmful","Harmful"),("safety","Safety concern"),("other","Other")])
    body = TextField(blank=True)
    contact_email = EmailField(blank=True)  # for anonymous takedown form
    created_at = DateTimeField(auto_now_add=True)
    resolved = BooleanField(default=False)
    resolution_notes = TextField(blank=True)
    resolved_by = FK(User, null=True, blank=True, on_delete=SET_NULL)

    class Meta:
        constraints = [
            CheckConstraint(
                check=(
                    Q(organizer__isnull=False, event__isnull=True, review__isnull=True)
                    | Q(organizer__isnull=True, event__isnull=False, review__isnull=True)
                    | Q(organizer__isnull=True, event__isnull=True, review__isnull=False)
                ),
                name="flag_targets_exactly_one",
            ),
        ]
```
Auto-hide evaluation: only flags from authenticated users (`reporter IS NOT NULL`) count toward `AUTO_HIDE_FLAG_THRESHOLD`. Anonymous takedown-form flags are stored but do not trigger auto-hide.

### Denormalized aggregates (F8) — new fields on existing models
Added to existing models as fields, not separate tables:
- `Organizer.follower_count: IntegerField(default=0)`
- `Organizer.avg_rating: FloatField(null=True)`
- `Organizer.rating_count: IntegerField(default=0)`
- `Event.attendance_count: IntegerField(default=0)`
- `Event.interested_count: IntegerField(default=0)`
- `Event.rating_count: IntegerField(default=0)` — collected, not displayed
- `Organizer.hidden: BooleanField(default=False)` — set True when authenticated flag count ≥ `AUTO_HIDE_FLAG_THRESHOLD`; filtered from public querysets via `.visible()` manager
- `Event.hidden: BooleanField(default=False)` — same auto-hide rule

**Update cadence:** Most aggregate fields follow the nightly `recompute_aggregates` pattern (F8). Two exceptions are evaluated synchronously in the request path:
- `hidden` — evaluated on each new authenticated flag creation (security-sensitive; cannot wait for nightly job). Set in the flag-creation view, not via Django signals.
- `rating_count` — updated synchronously on review submission as an optimization for the display threshold (`MIN_RATINGS_FOR_DISPLAY`). Without this, the 3rd review's author would see no rating displayed until the nightly job runs.

**Named thresholds** (tunable via `FeatureFlag` or named constants):
- `AUTO_HIDE_FLAG_THRESHOLD = 3` — authenticated flags to auto-hide a target
- `MIN_RATINGS_FOR_DISPLAY = 3` — minimum reviews before organizer rating is shown

### `core.FeatureFlag` — new DB-backed flags
```python
class FeatureFlag(models.Model):
    key = CharField(max_length=100, unique=True)
    enabled = BooleanField(default=True)
    description = TextField(blank=True)
    updated_at = DateTimeField(auto_now=True)
    updated_by = FK(User, null=True, blank=True, on_delete=SET_NULL)
```

Admin one-page view lists all flags with toggle switches. A cached `get_flag(key, default)` helper is the single read path for all code (middleware, views, context processors, templates).

## Test plan

- Legal pages return 200 and are linked from footer (footer rewrite verified — no placeholder links remain).
- Age gate: first request → 303 to `/age-check`; after acceptance, cookie set, normal routes work. Verify crawler user agents bypass the age gate. Verify age gate bypasses when `PUBLIC_READ_ENABLED=False`.
- Takedown form submission → `Flag` created (with `reporter=null`) + async email notification queued. Rate limiting: 6th submission from same IP within an hour → 429.
- Privacy enforcement from 0.4 still holds on public routes (private venue coords hidden from anon).
- Auto-hide: creating `AUTO_HIDE_FLAG_THRESHOLD` authenticated-user `Flag` rows on one target → target filtered from `.visible()` queryset. Anonymous flags do NOT count toward threshold.
- Review uniqueness: second review by same author for same organizer → updates existing review (no duplicate).
- Organizer rating display: only shows when `rating_count >= MIN_RATINGS_FOR_DISPLAY`.
- Event rating collection: form submission creates `Review` with `event_fk` set; `/events/<org_slug>/<event_slug>/` does NOT display any rating UI beyond "rate this event" button.
- Feature flag: flipping `RATINGS_ENABLED=False` hides rating form + display everywhere. All flags readable via `get_flag()` helper.
- Nightly aggregate task: manually trigger, assert counts match underlying queries.
- Flag model CheckConstraint: cannot create a Flag targeting zero or multiple entities.
- Rollback: flipping `PUBLIC_READ_ENABLED=False` → login wall re-enables on conditional routes, `robots.txt` returns `Disallow: /`, OG tags suppressed, `X-Robots-Tag` header restored, age gate bypassed. Legal pages remain reachable.
- Slug migration: GeoJSON payload has no `event_id`; map.js constructs slug-based drawer URLs; Alpine store uses composite key.
- Hidden filter: `.visible()` manager used in event_list, event_detail, event_drawer, organizer_profile (upcoming + past events).

## Go/no-go to 0.6

- Site has been public for 2 weeks with zero legal complaints.
- No privacy bypass discovered (private venues stay blurred to anon).
- Organizer review signal denoises: at least 3 organizers have ≥3 reviews, average ratings look plausible.
- Flag triage: average <10 min/day processing email digest.

## Rollback

- Flip `PUBLIC_READ_ENABLED=False` → login-wall middleware re-enables on `PUBLIC_READ_PREFIXES` (back to 0.4 posture). `ALWAYS_PUBLIC_PREFIXES` (legal pages, accounts, healthz, age-check) remain reachable.
- `robots.txt` automatically reverts to `Disallow: /` (dynamic view checks the flag).
- `X-Robots-Tag: noindex, nofollow, noarchive` header automatically re-enabled on all responses.
- OG meta tags suppressed (template conditional on `PUBLIC_READ_ENABLED`).
- `AgeGateMiddleware` bypasses itself when `PUBLIC_READ_ENABLED=False` — no age check in closed-beta posture.
- `RATINGS_ENABLED=False` hides form + display.
- `FLAGS_ENABLED=False` hides flag buttons; existing flags remain in admin.
- Legal pages stay published regardless.
