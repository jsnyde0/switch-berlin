## Legal gate (ships as one sprint before 0.5 public opening)

**This is the compliance sprint. Agent-reviewed, not lawyer-reviewed (per ADR-002 D2 — accepted risk).** Checklist:

### JuSchG — age gate
- Pre-auth middleware: first request without `age_gate=ok` cookie → interstitial page "You must be 18+ to enter. [Yes, I am 18+] [Leave]."
- Cookie is session-only or 365-day persistent at user's choice.
- Applies to every route except `/impressum`, `/privacy`, `/terms`, `/healthz`.
- German + English copy.

### DSA — takedown + contact
- `/impressum` page with responsible party details (maintainer name + address).
- `/takedown` endpoint: form (event URL, reason, reporter email, optional identity verification).
- Email relay: submissions land in a filtered Gmail label (no ticketing system per ADR-002).
- Published SLA: "We aim to review takedown requests within 72 hours."
- Trusted Flagger handling: placeholder endpoint; no registered flaggers yet.

### GDPR — consent + opt-out
- `Organizer.consent_*` fields populated since 0.2 (F5). This is when they become legally load-bearing.
- `/organizer-opt-out` endpoint: form where an organizer can request removal. Validates identity via email confirmation or Telegram handle match.
- Data-retention policy: `RawMessage` purged after 90 days (django-q2 nightly task from 0.2 continues).
- `/privacy` page explains: what data we collect (events, organizer info, user account, attendance), lawful basis per category, retention, rights.
- Cookie policy: if only session cookies used → no banner. Otherwise banner (prefer avoiding it by avoiding tracking cookies).

### Legal pages
- `/impressum` (German law requires; even for hobby projects)
- `/privacy` (data handling)
- `/terms` (user obligations, content policy, takedown process)
- All linked from every page footer.

### Telegram bot
- First interaction: consent text already live since 0.2. Verify wording matches finalized privacy policy.

### Hardening (pre-public)
- Switch drawer endpoint from PK-based (`/events/<int:event_id>/drawer/`) to slug-based (`/events/<org_slug>/<event_slug>/drawer/`) to avoid leaking sequential database IDs in the GeoJSON marker payload once the site is public. (Tracked from phase-0.4 spike review.)

### Finalize
- Agent review of each legal document. Record findings in a risk-log appendix.
- Explicit risk-acceptance statement in `docs/legal-risk-acceptance-2026-XX-XX.md`.

## Scope (post-gate)

**In:**
- Login-wall middleware **removed from public read routes** (`/events`, `/events/<slug>`, `/o/<slug>`, `/impressum`, `/privacy`, `/terms`, `/takedown`).
- Signup still invite-only; all writes (attend, follow, future review/flag) still require approved account.
- `robots.txt` opens up (allow crawling of public routes). OG tags on event + organizer pages (per ADR-002 D4 "trap feature" — OG tags are fine NOW that we're post-gate).
- Organizer ratings DISPLAYED (threshold ≥3 per ADR-003 F2): on `/o/<slug>`, show average + count.
- Event ratings COLLECTED (form works, row saved) but NOT DISPLAYED (per ADR-003 F2 — wait for 0.7 when per-event N supports threshold).
- Flag / report endpoint: flag button on every event + organizer page. Flags land in `Flag` model. Triage via email digest (F9 — no in-app triage UI).
- Auto-hide rule: `N` flags on a single target → hide from public (admin still sees). Initial `N=3`.
- Kill-switches (F9): `SIGNUP_OPEN`, `RATINGS_ENABLED`, `FLAGS_ENABLED`, `PUBLIC_READ_ENABLED` — each flippable in admin.
- Nightly `django-q2` task: recompute `Organizer.follower_count`, `Event.attendance_count`, `Organizer.avg_rating` (F8).

**Out:**
- Open (non-invite) signup — phase 1.0 (admin-reviewed form).
- Event reviews displayed — phase 0.7.
- Organizer self-service edits — phase 1.0.
- In-app moderation console — ADR-002 D4 cut; email digest only.

## Data model deltas

### `reviews.Flag`
```python
class Flag(models.Model):
    reporter = FK(User, null=True, blank=True, on_delete=SET_NULL)  # null = anonymous takedown form
    organizer = FK(Organizer, null=True, blank=True, on_delete=CASCADE, related_name="flags")
    event = FK(Event, null=True, blank=True, on_delete=CASCADE, related_name="flags")
    review = FK("reviews.Review", null=True, blank=True, on_delete=CASCADE, related_name="flags")
    reason = CharField(choices=[("spam","Spam"),("inaccurate","Inaccurate"),("harmful","Harmful"),("safety","Safety concern"),("other","Other")])
    body = TextField(blank=True)
    contact_email = EmailField(blank=True)  # for anonymous takedown form
    created_at = DateTimeField(auto_now_add=True)
    resolved = BooleanField(default=False)
    resolution_notes = TextField(blank=True)
    resolved_by = FK(User, null=True, blank=True, on_delete=SET_NULL)
```

### Denormalized aggregates (F8)
Added to existing models as fields, not separate tables:
- `Organizer.follower_count: IntegerField(default=0)`
- `Organizer.avg_rating: FloatField(null=True)`
- `Organizer.rating_count: IntegerField(default=0)`
- `Event.attendance_count: IntegerField(default=0)`
- `Event.interested_count: IntegerField(default=0)`
- `Event.rating_count: IntegerField(default=0)` — collected, not displayed
- Nightly `recompute_aggregates` task updates all.

### `core.FeatureFlag`
```python
class FeatureFlag(models.Model):
    key = CharField(max_length=100, unique=True)
    enabled = BooleanField(default=True)
    description = TextField(blank=True)
    updated_at = DateTimeField(auto_now=True)
    updated_by = FK(User, null=True, blank=True, on_delete=SET_NULL)
```

Admin one-page view lists all flags with toggle switches.

## Test plan

- Legal pages return 200 and are linked from footer.
- Age gate: first request → 303 to `/age-check`; after acceptance, cookie set, normal routes work.
- Takedown form submission → `Flag` created + email relay fires.
- Privacy enforcement from 0.4 still holds on public routes (private venue coords hidden from anon).
- Review auto-hide: creating 3 `Flag` rows on one target → target `.hidden=True` (or equivalent filter on public queryset).
- Organizer rating display: only shows when `rating_count >= 3`.
- Event rating collection: form submission creates `Review` with `event_fk` set; `/events/<slug>` does NOT display any rating UI beyond "rate this event" button.
- Feature flag: flipping `RATINGS_ENABLED=False` hides rating form + display everywhere.
- Nightly aggregate task: manually trigger, assert counts match underlying queries.

## Go/no-go to 0.6

- Site has been public for 2 weeks with zero legal complaints.
- No privacy bypass discovered (private venues stay blurred to anon).
- Organizer review signal denoises: at least 3 organizers have ≥3 reviews, average ratings look plausible.
- Flag triage: average <10 min/day processing email digest.

## Rollback

- Flip `PUBLIC_READ_ENABLED=False` → login-wall middleware re-enables everywhere (back to 0.4 posture).
- `RATINGS_ENABLED=False` hides form + display.
- `FLAGS_ENABLED=False` hides flag buttons; existing flags remain in admin.
- Legal pages stay published regardless.
