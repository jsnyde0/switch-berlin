# Phase 0.1 — Schema + admin + manual entry

**Date:** 2026-04-17 (revised post design-review pass 1)
**Status:** Draft (target: phase start)
**Parent roadmap:** [§0.1](2026-04-17-roadmap-0.1-to-1.0.md#01--schema--admin--manual-entry-private)
**ADRs:** [ADR-001 D5/D8](../decisions/ADR-001-core-product-and-stack.md), [ADR-003 F1–F7](../decisions/ADR-003-cheap-foresight-patterns.md)
**Target state:** [1.0 design](2026-04-17-v0-design.md)
**Audience:** maintainer only. No auth UI, no public surface, no ingestion pipeline.
**Risk killed:** schema can't represent real Berlin events.

## Scope

**In:**
- Django apps: `accounts`, `organizers`, `venues`, `events`, `ingestion`, `reviews`.
  - `accounts` ships **first** — a custom `AbstractUser` subclass with `AUTH_USER_MODEL = "accounts.User"` set in settings **before any other migration runs**. Retrofitting a custom user model after migrations exist is the single most expensive Django migration trap; we pay the cost now.
- Ingestion **schema only** (tables: `RawMessage`, `SourceFailure`). No bot, no enrichment, no extraction — that is the phase 0.2 pipeline.
- Normalized schema per ADR-001 D8 with ADR-003 foresight patterns F1–F7 baked in.
- `CREATE EXTENSION vector` via migration (F1 — extension on, no `VectorField` yet). Compose image must be `pgvector/pgvector:pg17` (verify `compose.yaml` before migrating).
- F5 (GDPR consent fields) **pulled forward from 0.2 to 0.1** — trivial additive column set on `Organizer`, avoids a second migration. ADR-003 F5 text predates this decision; update ADR-003 to reflect.
- Django admin customizations: list displays, search fields, list filters, inline raw↔parsed on `Event`, bulk actions (publish, reject, archive on `Event`; "mark approved + record consent" on `Organizer`).
- Approval flag on `User` (`is_approved: bool`) + middleware placeholder (field exists, middleware registered but wired to no route yet).
- i18n actually wired: `USE_I18N=True`, `LocaleMiddleware` in `MIDDLEWARE`, `LANGUAGES = [("en", ...), ("de", ...)]`, `LOCALE_PATHS` set. `{% trans %}` wrappers on every user-facing string from day 1 (F6). CI must run `django-admin makemessages -l de` cleanly.
- `django-q2` wired to Postgres broker, plus a real heartbeat task (see Test plan / Go-no-go).
- CI: ruff, djlint, pytest smoke test per model, `makemigrations --check`, `makemessages` clean.

**Out:**
- Ingestion **pipeline** (Telegram bot, URL enrichment, LLM extraction) — phase 0.2.
- Public templates, HTMX surface, React island — phase 0.3+.
- Auth/allauth wiring beyond the `is_approved` field — phase 0.3+.
- Any kill-switch infrastructure (F9) — added per-feature as those features ship.
- `/admin/` → `/thebaws/` rename — mild obscurity is not security and complicates allauth defaults. Revisit at 0.5 legal-gate hardening.
- Admin "merge-duplicates" bulk action — real implementation needs FK rewrites across `Event`/`Review`; at 30 manual events duplicate pressure is low. Defer to 0.2 once ingestion creates real pressure.
- `core.FeatureFlag` substrate — premature for 0.1 (no flagged features yet).

## FK convention

All foreign keys to the user model use the string form `settings.AUTH_USER_MODEL`, never a direct import of the user class. This avoids import-order breakage with the custom user model. Never call `get_user_model()` at module import time in models.

### `events.Event`
```python
class Event(models.Model):
    title = CharField(max_length=300)
    slug = SlugField(max_length=200)  # unique per-organizer, see Meta.constraints
    description = TextField(blank=True)
    organizer = FK(Organizer, on_delete=PROTECT, related_name="events")
    venue = FK(Venue, on_delete=PROTECT, null=True, blank=True, related_name="events")
    tags = M2M(Tag, blank=True, related_name="events")

    # Time — no per-event timezone in 0.1 (settings.TIME_ZONE=Europe/Berlin covers single-city).
    # Add per-event timezone when city #2 arrives; that migration is accepted as "real" per ADR-003.
    start = DateTimeField()
    end = DateTimeField(null=True, blank=True)

    # Price
    price_min_cents = IntegerField(null=True, blank=True)
    price_max_cents = IntegerField(null=True, blank=True)
    currency = CharField(max_length=3, default="EUR")
    is_free = BooleanField(default=False)
    sliding_scale = BooleanField(default=False)

    # External
    external_url = URLField(blank=True)
    tickets_url = URLField(blank=True)

    # Lifecycle — aligned with ADR-001 D8.
    # draft → review → published → (cancelled | rejected)
    # archived is a separate axis meaning "past event, hidden from default queries"; not enforced at DB level.
    status = CharField(
        choices=[
            ("draft","Draft"),
            ("review","Needs review"),
            ("published","Published"),
            ("cancelled","Cancelled"),
            ("rejected","Rejected"),
            ("archived","Archived"),
        ],
        default="draft",
    )
    published_at = DateTimeField(null=True, blank=True)

    # Provenance (F7)
    raw_message = FK("ingestion.RawMessage", null=True, blank=True, on_delete=SET_NULL)

    # Cheap foresight: NO VectorField (F1). Add via additive migration when needed.

    created_at = DateTimeField(auto_now_add=True)
    updated_at = DateTimeField(auto_now=True)

    class Meta:
        indexes = [Index(fields=["status","start"]), Index(fields=["organizer","start"])]
        constraints = [
            UniqueConstraint(fields=["organizer","slug"], name="event_slug_unique_per_organizer"),
            # Soft dup-guard for manual entry: same organizer can't have two events at the same start with the same title.
            UniqueConstraint(fields=["organizer","start","title"], name="event_dup_guard_org_start_title"),
        ]
```

### `reviews.Review` (F2)
```python
class Review(models.Model):
    author = FK(settings.AUTH_USER_MODEL, on_delete=CASCADE, related_name="reviews")
    organizer = FK(Organizer, null=True, blank=True, on_delete=CASCADE, related_name="reviews")
    event = FK(Event, null=True, blank=True, on_delete=CASCADE, related_name="reviews")

                name="review_targets_exactly_one",
            ),
        ]
```

## Admin customizations

- **OrganizerAdmin:** list_display (name, status, verified_badge, event_count), list_filter (status, verified_badge), search_fields (name, slug, telegram_channel), readonly on timestamps. Bulk action: "Mark approved + record consent".
- **EventAdmin:** list_display (title, organizer, start, status), list_filter (status, start, tags, organizer), search_fields (title, description), inline `EventImage`, side-panel showing linked `RawMessage.text` and `enriched_payload`. Bulk actions: publish, reject, archive.
- **RawMessageAdmin:** list_display (source_type, received_at, extraction_status, short text preview), filter by extraction_status. Read-only in 0.1 (no actions until 0.2 extraction pipeline).
- **ReviewAdmin:** list_display (author, target_display, rating, created_at), target_display computed from organizer XOR event.

## Test plan

- `pytest` smoke tests: every model round-trips create/read.
- `Review` constraint: saving with both `organizer` and `event` set raises IntegrityError; saving with neither raises too.
- `Event` constraints: duplicate `(organizer, slug)` raises IntegrityError; duplicate `(organizer, start, title)` raises IntegrityError.
- `Event.status` transitions: draft → review → published → (cancelled|archived) allowed at application level; archived → draft not enforced at DB level (documented admin convention).
- Admin smoke test: `GET /admin/` returns 302 unauth, 200 after superuser login.
- `django-q2` heartbeat: `ingestion.tasks.heartbeat` scheduled every 5 minutes; inserts a `HeartbeatLog` row and emits a Logfire info event. Go/no-go checks `HeartbeatLog.objects.filter(ran_at__gte=now()-24h).count() >= 280` (288 expected, small slack).
- Migration check: `python manage.py makemigrations --check` is clean after the phase. `CREATE EXTENSION vector` migration runs against the `pgvector/pgvector:pg17` compose image on a fresh DB without error.
- i18n bootstrap: `python manage.py makemessages -l de` runs clean and produces a non-empty `locale/de/LC_MESSAGES/django.po`. Settings assert: `LocaleMiddleware` present, `LANGUAGES` includes at least `en` and `de`.
- CI: ruff (python), djlint (templates), pytest, `makemigrations --check`, `makemessages` — all green before merge.

## Go/no-go to 0.2

- Maintainer hand-enters ≥30 real Berlin events spanning ≥8 organizers.
- Zero fields feel like workarounds (document any workaround; if >1, this phase is not done).
- Admin review workflow (approve/publish) takes <30 seconds per event.
- `django-q2` heartbeat has ≥280 `HeartbeatLog` rows in the last 24h with no worker crash in Logfire.
- `makemessages -l de` produces a non-empty catalog containing every user-facing string in templates/admin.

## Rollback

Phase is purely additive (new tables). Rollback = migrate backward to zero + drop the new apps from `INSTALLED_APPS`. The `vector` Postgres extension is **not** dropped by the reverse migration (data-loss risk on shared DB); it is left installed. No public traffic yet, no user data to preserve.
