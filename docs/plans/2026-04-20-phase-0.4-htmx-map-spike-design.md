## Why a spike, not a phase

ADR-002 D3 deferred the React-island decision to end-of-0.3, to be made on evidence. ADR-004 resolved it to HTMX-default with objective tripwires. This doc is the executable version of that resolution: a bounded spike that either becomes Phase 0.4 (when tripwires hold) or dies cleanly so the React-island fallback can run (if any tripwire fires).

The spike is NOT throwaway-by-default. Its acceptance criteria are a subset of Phase 0.4's scope. Passing it ships that subset.

## Scope (minimum to stress the architecture, not more)

**In:**
1. MapLibre GL JS map pinned via `hx-preserve` on `/events`; single `<div id="map">` that never gets swapped.
2. Existing filter chips + date + price filter → HTMX re-fetch of list partial AND emission of a `events:filter-changed` window event the map listens to.
3. URL-sync on filters and map bounds: `/events?tags=a,b&date=weekend&bounds=lat1,lng1,lat2,lng2` — shareable, survives reload and back/forward nav.
4. Click marker → side-drawer opens with event detail (HTMX partial into `#drawer`); list item for that event gets `.selected` class.
5. Click list card → map pans to marker + marker gets `.highlighted` class.
6. Privacy handling per venue mode: `public` → exact pin; `neighborhood_blur` → pin at 3-decimal-rounded coords with `blur_radius_m` circle (default 250 m); `private` → 1000 m circle at deterministic fake center (slug-hash derived), no pin. Server enforces: exact lat/lng absent from GeoJSON for non-public venues.
7. Selection state in URL: `?selected=<event-id>` — opening the drawer pushes a history entry so back closes it and forward re-opens it.

**Out of spike (deferred to rest of Phase 0.4):**
- Invite-code signup flow + `LoginWallMiddleware` relaxation (`is_staff` → `is_approved`).
- `Attendance` + `OrganizerFollow` buttons (wire after spike graduates).
- Self-hosted tile server (start with OSM community server; swap in Phase 0.5+ if load warrants).
- Clustering beyond MapLibre's built-in `cluster: true` on the source.

## Architecture — the pattern we're validating

```
┌─────────────────────────────────────────────────────────────────┐
│  /events page (server-rendered shell)                           │
│                                                                 │
│  ┌──────────┐  ┌──────────────────┐  ┌──────────────────────┐  │
│  │ Filter   │  │ Event list       │  │ Map                  │  │
│  │ chips    │  │ (HTMX partial)   │  │ (hx-preserve="true") │  │
│  │ (Alpine) │  │ #event-list      │  │ #map                 │  │
│  └────┬─────┘  └────────┬─────────┘  └──────────┬───────────┘  │
│       │                 │                       │              │
│       └────── Alpine.store('map', {...}) ───────┘              │
│                         │                                      │
│                window events:                                  │
│                  events:filter-changed                         │
│                  events:selection-changed                      │
│                  events:bounds-changed                         │
│                                                                │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ Drawer (HTMX into #drawer)                               │  │
│  └──────────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
```

**Markers vs. list pagination:** The paginated list shows 20 events per page. The map must show markers for ALL events matching the current filters (not just the current page). The view returns both: (a) paginated list queryset for `#event-list`, and (b) a separate non-paginated markers queryset serialized as GeoJSON via `_event_markers.html`. At 500 events the full marker payload is ~50 KB — well within budget.

**Bounds filter:** Uses simple `latitude__gte/lte` + `longitude__gte/lte` on DecimalField (per ADR-003 F4; no PostGIS). Bounds filtering applies to the markers query only — the paginated list is not geo-filtered (users scroll the list to see events outside the current viewport).

**State ownership:**
- **Server:** canonical filter state (via URL query params), privacy enforcement, paginated event list + full marker set as GeoJSON.
- **Alpine store:** `selection` (current event id or null), `hoveredEventId`, `bounds` (mirrors URL).
- **Map instance:** pan/zoom only (MapLibre's own state).
- **No duplicated state.** Filter chips read URL via `htmx:configRequest`; map writes URL via `history.replaceState` on bounds change (bounds are viewport state, not filter state — not pushed to history); list markers come from the server alongside the list partial (single fetch).

**Communication contract** (what makes D3 escape hatch cheap):
- `window.dispatchEvent(new CustomEvent('events:filter-changed', {detail: {filters}}))` — after HTMX swap of list partial.
- `window.dispatchEvent(new CustomEvent('events:selection-changed', {detail: {eventId}}))` — from map OR list.
- `window.dispatchEvent(new CustomEvent('events:bounds-changed', {detail: {bounds}}))` — from map.
- Map module exposes `initMap(containerEl, store) → { destroy() }`. No globals beyond `window.Alpine`.

If we later swap in a React island, the island mounts on `#map`, subscribes to the same events, dispatches the same events back. Filter chips, list, drawer — zero changes.

## File layout

```
events/
  views.py                           # + bounds filter on markers query, + full GeoJSON marker payload
templates/
  events/
    list.html                        # shell: filter chips + #event-list + #map + #drawer
    _event_list.html                 # HTMX partial (existing, paginated)
    _event_markers.html              # {{ markers|json_script:"markers-data" }} — ALL matching events
    _event_drawer.html               # HTMX drawer partial
static/
  js/
    events/
      map.js                         # initMap() — MapLibre init, layer setup, event wiring
      store.js                       # Alpine.store('map', {...}) — single source of truth
      bridge.js                      # window event <-> store plumbing; HTMX afterSwap listener
venues/
  serializers.py                     # venue_to_geojson() with privacy enforcement per mode
```

Target: **< 300 LOC** total across `map.js + store.js + bridge.js` (T1 tripwire).

## Acceptance criteria (spike passes when all hold)

**Functional:**
- [ ] Map renders with markers at page load; `#map` has `hx-preserve="true"` and is never swapped.
- [ ] Changing any filter chip / date / price fires HTMX partial → `#event-list` swaps → markers update on map.
- [ ] URL reflects all filter state + map bounds; reloading the URL reproduces the exact view.
- [ ] Browser back/forward nav restores full state (filters, selection, bounds, drawer) without double-initializing the map.
- [ ] Click pin → drawer opens with that event; list row for that event gets `.selected`.
- [ ] Click list card → map pans to marker; marker gets `.highlighted`; other markers unhighlight.
- [ ] Privacy enforcement per venue mode: `public` → exact pin; `neighborhood_blur` → pin at blurred coords + radius circle; `private` → 1000 m obfuscation circle, no pin. Exact lat/lng absent from GeoJSON payload for non-public venues (verify in network tab).

**Non-functional:**
- [ ] `Server-Timing: partial;desc="event-list";dur=X` for filter partials < 100ms p95 on a seeded 500-event dataset.
- [ ] No `console.error` on load, filter, selection, or navigation.
- [ ] Integration tests cover: privacy enforcement (private venue coords absent for non-`going` user), URL round-trip (filter→URL→reload→same state), selection cross-wiring (server-side unit test of the event payload shape only — cross-panel interaction is tested manually).

**Code-quality gates (these are the tripwires):**
- [ ] **T1**: `wc -l static/js/events/*.js + grep -c '<script>' on templates/events/*.html` × estimated line count < **300**.
- [ ] **T2**: No single state-sync bug took > 2h to diagnose. (Kept in a scratch log during the spike.)
- [ ] **T3**: Back/forward navigation QA checklist passes without hacks.
- [ ] **T4**: The bridge pattern is implemented in exactly one place; no duplication across templates.
- [ ] **T5**: No `setTimeout`, no manual DOM hand-syncing outside the bridge, no monkey-patching MapLibre.

## Back/forward nav QA checklist (T3)

Run on Firefox + Chrome:

1. Load `/events` — note marker count.
2. Apply a tag filter — note new marker count + URL.
3. Click a marker — drawer opens, marker highlights.
4. Hit browser **back** — drawer closes, filter persists, marker count stays filtered, map still initialized (no blank canvas).
5. Hit browser **forward** — drawer re-opens to same event, selection restored.
6. Apply another filter that would empty the map — verify "no events in view" message, no crash.
7. Hit back → filters restore, markers reappear.
8. Pan the map → URL updates with bounds via `history.replaceState` (replaces current entry, does NOT push — bounds are viewport state).
9. Reload page → bounds, filters, selection all restored from URL.
10. Do all of the above with devtools open and confirm no `console.error` or `console.warn`.

**Note on `hx-push-url` + `replaceState` interaction:** Filter changes push history entries (`hx-push-url`). Map pans replace the current entry (`replaceState`). This means hitting "back" after a pan restores the pre-filter URL, not the pre-pan viewport. Expected behavior: back restores filters; map re-reads bounds from URL or falls back to fitting all markers. Bounds lost on back is acceptable — they are viewport state, not semantic state.

## If tripwires fire — React-island fallback spike

Same scope (1–7 above), same acceptance criteria, same privacy enforcement, same URL-sync contract.

- `frontend/src/events/EventsIsland.tsx` mounts at `#events-island` (replaces list + map + drawer).
- `/api/v1/events?bounds=…&tags=…&date=…` JSON endpoint (Django view, reuses the existing queryset + privacy serializer).
- Zustand store for `selection`, `hoveredEventId`, `bounds`, `filters`.
- Filter chips stay HTMX OR move into the island — decide on day 1 of the fallback spike based on how much the chips are already tangled.
- `@vis.gl/react-maplibre` for the map.
- `django-vite` for asset wiring (already scaffolded).

Time-box: 2 days. Deliverable: same acceptance criteria checked off, same Phase 0.4 scope satisfied. At end, write ADR-004 amendment recording what tripped and committing to the island.

## Out-of-spike prerequisites (must exist before spike starts)

- [x] Event URL scheme fix merged: `/events/<org-slug>/<event-slug>/`. Already implemented in `events/urls.py` and `events/views.py:event_detail`.
- [x] Seed data: 500 events across ≥8 organizers via `seed_spike_data.py`. **Gap:** command does not assign Tags to events (blocks tag filter testing) and does not set `is_free`/`price_min_cents`/`price_max_cents` (blocks price filter testing). Extend the seed command before starting the spike.
- [ ] Decide tile provider: OSM community server (`https://tile.openstreetmap.org/{z}/{x}/{y}.png`) vs tileserver-gl self-hosted. Community server is fine for the spike; note usage-policy compliance (valid `User-Agent`, no heavy traffic).

## Graduation to Phase 0.4 proper

- Relax `LoginWallMiddleware` from `is_staff` to `is_staff or is_approved`.
- `InviteCode` model + admin + signup adapter override.
