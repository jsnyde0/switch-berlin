# Phase 0.4 — Map + filter surface + invite-gated accounts

**Date:** 2026-04-17
**Status:** Draft (target: phase start; specifics refined after 0.3 React decision)
**Parent roadmap:** [§0.4](2026-04-17-roadmap-0.1-to-1.0.md#04--map--filter-surface-internal-only-still-login-walled)
**ADRs:** [ADR-001 D4, D5](../decisions/ADR-001-core-product-and-stack.md), [ADR-002 D3](../decisions/ADR-002-phased-rollout-and-legal-gate.md)
**Predecessor:** [phase 0.3](2026-04-17-phase-0.3-internal-events-design.md)
**Audience:** ~5–15 hand-picked insiders with invite codes. Still login-walled, still internal-only.
**Risk killed:** map privacy model is broken; map is too empty to be useful at invite-gated density.

## Scope

**In:**
- Map view on `/events` (MapLibre + OSM tiles, self-hosted or community tile server — NO Google Maps per ADR-002 D4).
- Neighborhood-blur circles for `Venue.privacy_mode='public'` (blur radius from `Venue.blur_radius_m`, default 250m).
- Private-venue mode: 1000m-radius circle instead of a pin; exact address only revealed to users who marked `Attendance.status='going'`.
- List-map two-way coupling: hover pin → highlight card; hover card → highlight pin.
- allauth invite-token signup flow: maintainer generates batch invite codes via admin; user redeems code + sets password + gets `is_approved=True` after admin one-click approval. Login-wall middleware now accepts `user.is_approved` (not just `is_staff`).
- Attend / interested buttons on event detail (per `Attendance` model below).
- Follow organizer button on `/o/<slug>` (per `OrganizerFollow` model).
- **React island OR HTMX+Alpine+MapLibre — decided at end of 0.3, implemented here.**

**Out:**
- Reviews (collected or displayed) — phase 0.5.
- Flagging — phase 0.5.
- Public access — phase 0.5 (after legal gate).
- Self-signup without invite — phase 1.0.
- Event-level reviews — phase 0.7.

## Data model deltas

### `events.Attendance`
```python
class Attendance(models.Model):
    user = FK(User, on_delete=CASCADE, related_name="attendances")
    event = FK(Event, on_delete=CASCADE, related_name="attendances")
    status = CharField(choices=[("interested","Interested"),("going","Going"),("went","Went")], default="interested")
    created_at = DateTimeField(auto_now_add=True)
    updated_at = DateTimeField(auto_now=True)

    class Meta:
        unique_together = [("user","event")]
```

### `organizers.OrganizerFollow`
```python
class OrganizerFollow(models.Model):
    user = FK(User, on_delete=CASCADE, related_name="follows")
    organizer = FK(Organizer, on_delete=CASCADE, related_name="followers")
    created_at = DateTimeField(auto_now_add=True)

    class Meta:
        unique_together = [("user","organizer")]
```

### `accounts.InviteCode`
```python
class InviteCode(models.Model):
    code = CharField(max_length=32, unique=True, default=generate_code)
    created_by = FK(User, on_delete=PROTECT, related_name="invites_created")
    created_at = DateTimeField(auto_now_add=True)
    redeemed_by = FK(User, null=True, blank=True, on_delete=SET_NULL, related_name="invite_redeemed")
    redeemed_at = DateTimeField(null=True, blank=True)
    expires_at = DateTimeField(null=True, blank=True)
    notes = TextField(blank=True)  # "for Anna at Shibari Club"
```

No caches or denormalized counts yet (F8: counts come via nightly recompute at 0.6 if needed).

## Map surface

- MapLibre GL JS. Tiles: OSM community server or self-hosted tileserver-gl (decide at phase start; if self-hosted, add to Compose).
- Default view: Berlin center, zoom 11.
- Pins for public venues; circles for private venues; cluster at low zoom.
- Clicking pin/circle → opens event detail in side-drawer (no page navigation).
- Neighborhood-blur: circle is rendered in place of the pin at all zoom levels for privacy venues. Exact coordinates NEVER sent to the client for private venues unless user has `Attendance.status='going'`.

### Privacy enforcement (server-side)
- Venue serializer: if `privacy_mode='private'` AND requesting user doesn't have `Attendance(event__venue=v, status='going')`, return blurred center (rounded to 3 decimal places of lat/lng, picked deterministically from venue slug hash) + radius.
- Never trust the client.

## Island vs HTMX implementation

If 0.3 chose React island:
- `frontend/src/pages/EventsIsland.tsx` — filter sidebar + list + map, shared state via Zustand or equivalent.
- django-vite renders at `/events`; SSR shell provides initial filter state via `json_script`.
- Server provides `/api/v1/events` JSON endpoint consumed by the island.

If 0.3 chose HTMX+Alpine+MapLibre:
- Map is a vanilla MapLibre instance initialized on page load.
- Filter changes trigger HTMX re-fetch of list partial AND a custom `events-changed` event that MapLibre listens for to re-render markers.
- Side-drawer event detail via `hx-target="#drawer"`.

## Invite flow

```
Maintainer admin: "Generate 10 invite codes" → 10 InviteCode rows
Maintainer DMs code to Anna
Anna visits /accounts/signup/?code=XXXX
  → allauth signup form (email, password, display name)
  → on signup, InviteCode.redeemed_by=anna
  → User.is_approved=False initially
Maintainer admin: sees Anna in "needs approval" queue → approves
  → User.is_approved=True → Anna can now access /events
```

## Follow + attend interactions

- Attend button on `/events/<slug>`: "Interested / Going / Went". HTMX POST to `/events/<slug>/attend/<status>/`, returns button swap.
- Follow button on `/o/<slug>`: "Follow / Following". HTMX POST to `/o/<slug>/follow/`.
- No counts shown publicly at 0.4 (F8 nightly recompute doesn't exist yet; raw queryset count is fine at this scale).

## Test plan

- Privacy enforcement: user without `going` Attendance CANNOT see private venue's exact coords via the JSON API. Parameterized across all access paths.
- Invite code redemption: unique-use (redeemed code rejects second redemption); expired code rejected.
- Login-wall middleware: anonymous → redirect; approved user → allowed; staff-only (no approval yet) → temporarily also allowed for backward-compat with 0.3 staff accounts.
- Map smoke test: page renders with ≥1 marker at staff zoom.
- Hover coupling test (if JS): event card hover adds `.highlighted` class to corresponding pin.
- E2E walkthrough: invite-code flow → signup → approval → browse map → attend event → see correct private-venue coords.

## Go/no-go to legal gate

- ≥3 private-venue organizers approve the blur as drawn (DM them a screenshot; verbal ok).
- ≥40 published events so the map isn't sad.
- No organizer complaint about their representation on the map.
- Attendance + follow working; no user has managed to bypass privacy enforcement.

## Rollback

- Flip `MAP_ENABLED=False` env var → template hides map tab; list-only view.
- Flip `INVITES_ENABLED=False` → signup form 503s; existing accounts still work.
- Attendance and follow rows persist; removing buttons doesn't lose data.
