## Scope

**In:**
- Server-rendered templates: `/events` list, `/events/<slug>` detail, `/o/<slug>` organizer profile.
- Filters on `/events`: date range, tags, organizer, price (free/paid). HTMX-first implementation.
- Hard login-wall middleware: anonymous requests to any non-auth route → 403 or redirect to `/login`.
- `robots.txt` disallow-all. No OpenGraph tags. `X-Robots-Tag: noindex, nofollow` header on every response.
- allauth configured but signup CLOSED. Maintainer mints staff accounts by admin; organizer-peer gets one; 2–3 friends get one.
- Cotton components for cards (event card, organizer mini-card).
- Tailwind v4 + DaisyUI across all server-rendered pages.
- URL-synced filter state via query params (`?tags=shibari,play-party&from=2026-05-01`).

**Out:**
- React island on `/events` — **DECIDED AT END OF PHASE** (see ADR-002 D3). Build HTMX-first; if the surface feels fine, cut the island entirely. If seams appear, ship island at 0.4.
- Map view — phase 0.4.
- Attend / interested / follow / rate — phase 0.4+.
- Public access — phase 0.5 after the legal gate.
- Any signup form — phase 0.4 (invite-token) / phase 1.0 (admin-reviewed).

## Login-wall middleware

```python
class LoginWallMiddleware:
    PUBLIC_PATHS = {"/accounts/login/", "/accounts/logout/", "/healthz", "/robots.txt"}

    def __call__(self, request):
        if request.path not in self.PUBLIC_PATHS and not request.user.is_authenticated:
            return redirect(f"/accounts/login/?next={request.path}")
        if request.user.is_authenticated and not request.user.is_staff:
            # 0.3 is staff-only; approved-but-not-staff users don't exist yet
            return HttpResponseForbidden("Not available yet.")
        response = self.get_response(request)
        response["X-Robots-Tag"] = "noindex, nofollow, noarchive"
        return response
```

At 0.4 this middleware relaxes to `user.is_approved`; at 0.5 it's removed from public routes entirely.

### `/events` list view
- Default sort: `start ASC` where `start > now`.
- Filters render as DaisyUI badges; clicking toggles, HTMX re-fetches the list partial.
- Pagination or infinite-scroll (HTMX + `hx-trigger="revealed"`) — default to pagination at 0.3 for simplicity.
- URL state sync: filter changes update `window.location.search` via `hx-push-url="true"`.

### `/events/<slug>` detail
- Cover image (if any), title, organizer mini-card, date/time, venue (name + neighborhood; NO map yet), tags, price, description, external ticket CTA, safety note footer.

### `/o/<slug>` organizer profile
- Avatar, name, verified badge, description, website, telegram handle, upcoming events list, past events (collapsed).
- **This is the page the organizer-peer reviews.** Link it to them at phase start; collect corrections.

## Decision gate at end of phase

Answer one question: **does HTMX + Alpine carry `/events` cleanly, or do we need the React island?**

**Indicators HTMX is enough (→ cut island, revisit post-1.0):**
- Filter changes feel snappy (<100ms to re-render list partial).
- Query-string state stays clean and shareable.
- No places where we had to write >20 lines of Alpine to coordinate two pieces of state.

**Indicators to ship the island at 0.4 (→ keep ADR-001 D5):**
- Multi-select filter + sort + pagination state got tangled.
- Anticipating the map view requires bidirectional sidebar↔map coupling that'll be ugly in Alpine.
- `hx-push-url` + filter history has edge cases (back button breaking).

Whichever way it goes, record the decision in a new ADR-004 at the end of the phase.

## Test plan

- View smoke tests: `/events`, `/events/<slug>`, `/o/<slug>` all return 200 for staff user.
- Login-wall: anonymous GET `/events` → 302 to `/accounts/login/`. Non-staff authenticated user → 403.
- Filter correctness: parameterized test asserts `?tags=X` filters the queryset correctly.
- `robots.txt` served disallow-all; `X-Robots-Tag` header present on all responses.
- djlint passes on all new templates.
- Manual dogfooding checklist: organizer-peer receives their `/o/<slug>` link + survey ("is this accurate? what's missing?").

## Go/no-go to 0.4

- Organizer-peer approves their profile page ("this looks accurate / I'd send people here").
- ≥5 staff/friend accounts browse `/events` across a week without reported bugs.
- HTMX-vs-island decision made and recorded as ADR-004.
- At least 40 published events across 5 organizers (density check — if below, pause and forward more Telegram posts).

## Rollback

- Login-wall middleware flip: route exclusions list can shrink to zero to re-lock everything.
- No public data yet; all routes are staff-only. Rolling back templates is a template-only change.
