## Scope

**In:**
- Signal threshold tuning based on 0.5 real-data observation. Defaults (revise at phase start):
  - Organizer ratings: display at ≥3 ratings (unchanged from 0.5).
  - Attendance counts: display at ≥5 attendances.
  - Follower counts: display at ≥5 followers.
  - Auto-hide flag threshold: adjust from 0.5 default of 3 based on false-positive rate.
- Moderation ergonomics: email digest format improvements, pre-filled resolution actions ("approve", "hide", "delete"), keyboard shortcuts in admin for flag resolution.
- Organizer reviews surface more prominently on `/o/<slug>` (dedicated section vs. sidebar).
- Trending sort on `/events`: weight by `interested_count * recency_decay + attendance_count * 2`. Default sort stays chronological; trending is a toggle.
- "Events your followed organizers posted" section on logged-in `/events` landing.

**Out:**
- Event-level reviews displayed — phase 0.7.
- Any messaging / DMs — banned per ADR-002 D4.
- Recommendation engine / embeddings — post-1.0.
- Organizer self-edit — phase 1.0.

## UI deltas

- `/o/<slug>`: reviews section upgraded (sortable by recent / highest / lowest, show reviewer's display name + date).

## Moderation improvements

- Email digest at 08:00 Europe/Berlin, lists flags from past 24h grouped by target.
- Each flag row in admin has one-click actions: "Approve (no action)", "Hide target", "Delete review", "Suspend organizer".
- Transparency log: `ModerationAction` table tracks every admin action for future DSA transparency report.

### `core.ModerationAction` (NEW, lightweight)
```python
class ModerationAction(models.Model):
    moderator = FK(User, on_delete=PROTECT)
    flag = FK("reviews.Flag", null=True, blank=True, on_delete=SET_NULL)
    target_type = CharField(max_length=50)  # 'event', 'organizer', 'review'
    target_id = IntegerField()
    action = CharField(max_length=50)  # 'no_action', 'hide', 'delete', 'suspend'
    reason = TextField(blank=True)
    created_at = DateTimeField(auto_now_add=True)
```

## Test plan

- Trending score: fixture with known counts + dates → assert ordering.
- Threshold toggling: flipping `threshold.organizer_ratings_display` via admin instantly changes public display.
- Moderation action logging: each admin action creates a `ModerationAction` row.
- Email digest task: mock 5 flags over 24h → assert one email sent with all 5.

## Go/no-go to 0.7

- Signals on ≥30% of upcoming events (interested, attending, or rated).
- Signal-to-noise ratio acceptable: ≤5% of flags are frivolous / troll.
- Zero brigading incidents (coordinated bad-faith flagging).
- Moderation load under 10 min/day averaged over 2 weeks.
- At least 5 events have ≥5 attendances each → per-event review threshold feasible for 0.7.

## Rollback

- Flip `TRENDING_SORT_ENABLED=False` → trending toggle hidden, chronological only.
- Thresholds revert to hardcoded defaults if config table causes issues.
- Moderation email digest: re-enable case-by-case notifications if digest misses something time-critical.
